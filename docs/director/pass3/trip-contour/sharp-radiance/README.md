# Sharp material radiance and separate extreme optical cue

Dan rejected the prior broad field as fog. His governing correction calls for sharper edge falloff, stronger contrast, and the material appearing to emit. The photographic flare in the Hoh Trip source is an optical exaggeration carried into painting, not a general instruction to surround Trip with haze. The direct identification of the photo-based forest image as Trip is retained; the private autobiographical account is not included here.

After that correction the asset agent reopened the actual purple/white-rim source1/277, reread the three source studies, and used Bee's new reading of1/277,2/115 and2/148. No source artwork was modified or pasted into the render.

All files here are runtime-only comparisons. The portal appearance module remains the prior provisional source while C.B./Bee review these pixels. The same white body, emission.45, pose, camera, dark stage, receiver block and point-light spill16 are held across three states: the prior broad field, the sharp local glow, and that sharp local glow plus an extreme optical streak. Receipts pin the frozen core and base appearance used for the runtime fixture.

`trial.json` records the initial sharp test: a12px blur at802px render width, cutoff curve `pow(smoothstep(.10,.48,mask),1.4)`, amplitude2.5 and a tint mixed toward white. It removed fog but read too much like a thin luminous edge to the asset agent. It is retained rather than relabeled successful.

`local-band/trial.json` records one bounded adjustment: blur32px, both active horizontal/vertical postprocesses explicitly set; `smoothstep(.06,.48,mask)`; source amplitude4 times the temperature tint. The field is confined to a near-surface band with a much steeper falloff, while space farther out stays dark. The custom merge shader divides the blurred premultiplied color by mask alpha to recover tint/amplitude, shapes the alpha, and adds the shaped field only outside the body stencil. The body itself retains the existing white PBR material and rounded shading.

The optional extreme cue is a Babylon LensFlareSystem anchored at `torso.upper`. It uses a newly generated procedural horizontal streak texture, not an imported photograph/artwork. Its camera-space size is1.6, position1 (at the projected emitter), and near-white color amplitude1.5. The texture combines a thin directional spine and compact bright center. Native LensFlareSystem visibility tests use a ray to the emitter and exclude the character/editor helpers from blockers; ordinary stage geometry can block it. The current screenshots show the visible case only; they do not independently establish an occlusion test yet. It is presented separately to review an extreme optical event, not forced into ordinary glow.

Both ordinary and extreme captures retain the same real PointLight and receiving block. The block's top/floor response is scene illumination, separate from the screen-space glow/flare. No new point-light shadow map is used. Both sets have desktop and mobile-emulated screenshots; phone-sized appearance is visible evidence, not a physical ACHE performance claim. No transparent-alpha improvement is claimed in this iteration.

The next production implementation, if this direction is authorized, must preserve both active blur axes across resize. Earlier receiving exposed Babylon9.37.1's asymmetric vertical-wrapper update and recreation from constructor options. That defect is documented in the superseded broad-field receipt and is not hidden by these fixed-size runtime captures.
