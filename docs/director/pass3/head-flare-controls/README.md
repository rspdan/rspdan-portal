# Independent head flare control

Trip's head flare is an explicit control from Off to 100%, separate from body glow. It remains saved while Ouch is selected and uses the same draft, Undo/Redo and immutable-save path as the other appearance settings. Older v2 takes omit the field and retain their previous normalized identity; the editor defaults it to Off.

The focused integrated UI check passed 24 assertions across desktop and a 390 by 844 mobile Chromium viewport, with no page errors. It exercised separate glow/flare values, Undo/Redo, character switching, browser drafts, an actual local-workspace save and reopening in a fresh browser context. The local save returned `shared: false`; no live Nest save or Crew send was used. Range values were delivered through the real controls' input/change events. This is functional UI receiving, not physical ACHE touch or performance evidence.

Evidence: [receiving.json](receiving.json), [desktop controls](desktop-controls.png), [mobile controls](mobile-controls.png), and [reproducible harness](receiving.py). The retained response-shape attempt records a fixture assumption that POST save returns a full take; the corrected harness reads the saved take using GET before reopening it.

Material appearance, flare location, occlusion and rendering quality are received separately in the Trip appearance study. The same core subsequently gained attachment and visible-effect controls for stage lights; those have separate integrated receiving.
